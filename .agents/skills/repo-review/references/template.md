## 2. レビュー判定と GitHub コメントメタデータ対応表

GitHub 管理対象レビュー（Pull Request レビュー等）において、AI エージェントは常に `--comment`（または `scripts/review-sync.sh comment reviewer --status <Approved|"Changes requested">`）を使用し、コメント本文先頭のメタデータで以下の通り判定を表明する：

| 内部レビュー判定 | メタデータ表記 (`- Status:`)  | 意味・運用                                                                                                                                                    |
| :--------------- | :---------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **GO**           | `- Status: Approved`          | PR の変更内容がマージ可能であることを表明（※ GitHub 公式の Approve ボタン押下およびマージは人間のみが担当）。P3 指摘のみの場合も GO（LGTM with nits）とする。 |
| **要修正**       | `- Status: Changes requested` | 未解消の確認済み Blocking 指摘（P0/P1、例外的 Blocking の P2）への修正対応を要求。                                                                            |
| **NO-GO**        | `- Status: Changes requested` | 設計方針やアーキテクチャの抜本的見直しまたは差し戻しを要求。                                                                                                  |

## 3. 人間報告フォーマット（Requester）

ローカルレビュー完了後、Requester がチャットで人間に報告する標準フォーマット：

```markdown
## レビュー対応完了

- レビュー記録: `docs/reviews/internal/<instance-id>/RVNNN.md`
- 判定: <GO | 要修正 | NO-GO>
- 対応概要: <対応内容の要約>
- INDEX: `docs/reviews/internal/<instance-id>/INDEX.md`
- 残存指摘・未対応: なし | <P3 指摘概要（再レビュー不要）や defer 項目>
```
